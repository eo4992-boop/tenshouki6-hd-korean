# NOBU6HD Runtime String Flow Trace V1

기존의 실행 중인 게임에 attach하여 이미 존재하는 문자열 주소를 감시하는 방식 대신, 게임을 트레이서가 직접 디버거 모드로 실행하여 프로세스 초기화 직후부터 문자열 접근을 잡는 실험용 런타임 트레이서입니다.

## 핵심 변경점
- NOBU6HD_JP.exe를 DEBUG_ONLY_THIS_PROCESS로 직접 실행합니다.
- CREATE_PROCESS_DEBUG_EVENT에서 게임의 첫 실행을 계속하기 전에 메모리를 검색합니다.
- 발견한 CP932/UTF-16 문자열 주소에 x86 하드웨어 데이터 브레이크포인트를 즉시 설치합니다.
- 새로 생성되는 스레드에도 동일한 브레이크포인트를 설치합니다.
- 후보가 4개보다 많으면 600ms마다 4개씩 순환합니다.
- [STRING ACCESS]가 발생하면 TID, DR6, EIP, 모듈/RVA, EIP 주변 명령 바이트를 기록합니다.
- 비정상/일반 예외도 기록하여 안티디버깅 여부를 판단할 단서를 남깁니다.

## 사용법
1. StringTrace.exe와 NOBU6HD_JP.exe를 같은 폴더에 둡니다.
2. 게임을 먼저 실행하지 말고 종료된 상태로 둡니다.
3. StringTrace.exe를 실행합니다.
4. 기본 추적 대상은 織田信長입니다.
5. 다른 문자열은 StringTrace.exe "文字列" 형식으로 지정합니다.
6. 트레이서가 게임을 자동으로 실행합니다.
7. 게임에서 해당 문자열이 표시되는 화면으로 이동합니다.
8. 몇 초간 동작시킨 뒤 게임을 종료합니다.
9. 생성된 nobu_runtime_string_trace.txt를 확인합니다.

## 중요한 로그
성공적으로 접근을 잡으면 [STRING ACCESS] tid=1234 dr=0 dr6=0x1 eip=0x401234 NOBU6HD_JP.exe eip=0x401234 rva=0x1234 bytes=8B 45 08 ... 형태로 기록됩니다.
여기서 NOBU6HD_JP.exe의 rva가 핵심입니다. 이 위치를 기준으로 게임의 실제 문자열 처리/렌더링 경로를 정적으로 추적할 수 있습니다.

## 이번 버전에서 확인하려는 것
### A. 기존 방식의 문제인지 확인
게임이 이미 실행된 뒤 attach했을 때 문자열 접근을 놓친 것이라면, 이번 버전에서는 프로세스의 첫 실행부터 감시하므로 [STRING ACCESS]가 나타날 수 있습니다.
### B. 문자열 원본이 실제 사용 버퍼인지 확인
FOUND로 검색되는 주소에 실제 CPU 접근이 발생하지 않는다면, 그 주소가 게임의 원본 데이터/문자열 테이블일 가능성이 있습니다.
### C. 안티디버깅 여부 확인
게임이 디버거 실행을 거부하거나 종료한다면 [DEBUG EXCEPTION]과 종료 코드를 함께 확인합니다. 단, 특정 예외 하나만으로 안티디버깅이라고 단정하지 않습니다.

## 주의
- 32비트(Win32) 전용입니다.
- 게임을 직접 실행하므로 기존에 실행 중인 NOBU6HD_JP.exe가 있으면 먼저 종료해야 합니다.
- 하드웨어 데이터 브레이크포인트는 x86에서 최대 4개이므로 후보가 많으면 순환합니다.
- 게임 EXE/DAT/N6P 파일은 수정하지 않습니다.
- 이번 버전은 문자열 출력 API를 후킹하는 도구가 아니라, 문자열 메모리의 실제 CPU 접근 흐름을 확인하는 진단 도구입니다.
